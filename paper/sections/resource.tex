\section{Dataset and Released Artifacts}
\label{sec:resource}
\subsection{An inferred resource for process analysis}
This resource links generated transcripts, worker summaries, factory vocabularies, inferred events, logs, and analysis artifacts from manual work in six factories. Readers can inspect how the pipeline constructs events and how those events support process measurements. The released labels and boundaries are inferred by the pipeline.

Assembly101~\cite{sener2022assembly101}, by comparison, records toy assembly and disassembly with simultaneous static and egocentric cameras. Its coarse and fine action annotations support benchmarks for recognition, anticipation, and temporal segmentation. The present resource serves a different purpose: its linked outputs make the construction and interpretation of process measurements inspectable.

Researchers can use the preserved generated transcripts to study alternative event representations, inspect which descriptions support a label, or compare how activity and process categories affect an aggregate. Such comparisons would examine representation choices unless independently checked against video. The present release includes structural checks and an author audit against generated transcripts, but no independent video annotations. Its inferred labels are not an independently annotated ground-truth benchmark for action recognition or boundary detection.

\subsection{Selection and provenance}
The archived subset contains outputs for factories \textbf{001} to \textbf{006}, with 59 worker identifiers and 322 paired generated transcript and event files. Factory and worker identifiers are inherited from the source organization. Domain descriptions in this paper summarize generated factory reports; they are not independently verified factory metadata. The archive does not record the selection rationale, the original source revision, or a complete inventory of the recordings available at extraction time. We therefore describe an available processed subset, not a random or representative sample of factories.

The current provider card reports a median clip length of 180 seconds~\cite{build2025egocentric}, whereas many archived generated transcript endpoints lie near 20 minutes. These describe different quantities and possibly different snapshots or subsets. The card documents a per-video \texttt{duration\_sec} field inside source archives, but those metadata files are not included here. The pipeline scans video files and does not preserve that field. The selected recordings' actual durations therefore cannot be established from the derived archive. The inspected public dataset snapshot does not identify the historical source version used for extraction.

The six per-video columns are \texttt{start\_timestamp}, \texttt{end\_timestamp}, \texttt{activity}, \texttt{process}, \texttt{factory}, and \texttt{worker}. S5 adds \texttt{source\_file}, \texttt{case\_id}, video-relative start and end offsets, and duration. The released dataset documentation follows the documentation concerns of Datasheets for Datasets~\cite{gebru2021datasheets}: composition, collection, uses, and limitations.

There are 13{,}304 generated transcript entries recognized by the original three-component timestamp parser. Recognizing the additional two-component and mixed-format entries gives 13{,}462 entries, without rescaling any timestamp.

Across all logs, the original endpoint-span calculation totals 786{,}412 seconds (218.4 hours). This sums parsed spans, not verified footage durations. Interval unions cover 414{,}886 seconds by counting overlapping time only once. Summed event durations total 421{,}283 seconds because each row contributes its full duration. Their difference, 6{,}397 seconds, is the additional time counted through overlaps.

The retained time-analysis subset contains 10{,}647 events in 320 logs, with 349{,}659 seconds of summed event duration (97.1 hours). This is the duration used for category shares; it is neither the full archive's endpoint span nor its interval-union duration.

\subsection{Temporal data quality and inclusion rules}
\label{sec:temporal}
Unusual generated transcript timestamps and exclusion from the time analysis are separate issues. The inclusion rule is applied to extracted event endpoints: a log is excluded when its largest event endpoint exceeds one hour. The original parser recognizes three-component timestamps; the broader parsing diagnostic also recognizes two-component and mixed-format entries. This explains the different entry counts above.

Table~\ref{tab:anomalies} identifies all seven generated transcripts whose literal parsed endpoint exceeds one hour. An endpoint of \texttt{20:06:00} paired with an event endpoint of \texttt{00:20:06} is consistent with a format error, but does not prove which timestamp is correct. Some files switch from \texttt{HH:MM:SS} to \texttt{MM:SS}. The analysis retains the recorded timestamps.

The original value-analysis code excludes a log only when its maximum event endpoint exceeds 3{,}600 seconds. It excludes two logs, both in factory \textbf{001}. This rule retains five logs associated with generated transcripts with unusual timestamps. Retention is a calculation rule, not certification of their timestamps.

Four other generated transcripts contain two-component endpoints. Their identifiers are \textbf{001}/004/00001, \textbf{002}/005/00001, \textbf{002}/009/00003, and \textbf{003}/003/00003. Three change format within the file; \textbf{002}/005/00001 uses \texttt{MM:SS} throughout. The original parser misses 158 entries across these files. The inclusion manifest records every video's formats, format-transition positions, endpoints, row count, union duration, summed duration, and decision. A separate interval manifest preserves the original endpoint strings. The low coverage ratios in Section~\ref{sec:consistency} therefore diagnose inconsistent representations; they do not establish long-video truncation.

\subsection{Synthetic time and case selection}
\label{sec:cases}
Each recording has its own local timeline. To combine recordings into a worker sequence, the merge shifts their event times onto a common artificial timeline. S4 stores local offsets as dates relative to 2000-01-01 for software compatibility. The archive provides no verified calendar times or cross-worker synchronization. S5 processes clips in filename order, which is not proof of their real chronological order.

For a worker's ordered clips $v_1,\ldots,v_m$, the last extracted event endpoint in recording $j$ is $M_j=\max_{e\in E_{v_j}}t_e$, with $M_j=0$ for an empty log. Let $O_j$ be the accumulated time shift for that recording, and let the primed endpoints be the shifted event times. S5 adds the preceding recording's endpoint to the accumulated shift and applies it to each event:
\begin{equation}
 O_1=0,\qquad O_{j+1}=O_j+M_j,\qquad
 (t_s',t_e')=(O_j+t_s,O_j+t_e).
\end{equation}
The same shift is added to both endpoints, preserving the event's duration. For example, if the first recording's last extracted endpoint is 60 seconds, an event at 10 to 20 seconds in the next recording appears at 70 to 80 seconds. The next clip starts at the largest extracted endpoint, not at the full source duration. Unrepresented trailing footage and empty logs add no elapsed time. Within-clip gaps before that endpoint remain on the synthetic axis, but gaps between recording sessions are unknown. Each worker has a separate synthetic origin; equal synthetic dates do not establish simultaneous work.
