\section{Introduction}
\label{sec:introduction}
\emph{Process mining} uses timestamped event records to study operational processes~\cite{vanDerAalst2016processmining}. Many manual factory tasks leave no such records. An information system may record an order or machine checkpoint while missing how a worker loads parts, moves material, checks a component, or switches tools. Video can make some of this work observable, but it does not directly provide the case identifiers, labels, and event boundaries that process mining needs~\cite{kratsch2022video}.

\emph{Egocentric video} records work from the camera wearer's perspective. The public Egocentric-10K resource provides factory recordings of this kind~\cite{build2025egocentric}. Figure~\ref{fig:egocentric} illustrates the viewpoint. Turning recordings into event logs requires decisions about what constitutes an event, which names to use, and how to interpret time. These are \emph{measurement decisions} as well as extraction tasks: they determine which aspects of work a log can represent and which questions an analysis can answer.

Prior work has shown how video can support workflow understanding~\cite{petersen2013workflows,pham2018workflow} and event-log construction~\cite{gavric2024multimodal}. Building on this work, we ask how recordings of manual factory work can be transformed into a \emph{shared event representation} whose construction and analytical meaning remain inspectable. Shared activity names allow observations from different recordings to be considered together. Understanding the resulting measurements also requires a clear account of how observations were selected, described, and grouped.

We present a construction method and a linked data resource for retrospective analysis of egocentric factory video. Pretrained models produce timestamped descriptions of visible work, which we call \emph{generated transcripts}, and use them to derive shared labels and event logs. Preserving the intermediate descriptions makes it possible to trace the resulting events to their textual basis. Figure~\ref{fig:dependency} gives an overview of the approach.

The paper makes three contributions:
\begin{itemize}
\item \textbf{A construction method.} We describe how pretrained models transform video descriptions into event logs with shared labels, making the representation choices explicit.
\item \textbf{A reusable resource.} We release linked descriptions, event logs, and analysis artifacts that support inspection and reuse of the construction process.
\item \textbf{An assessment of the resulting representation.} We examine the records' consistency, their use in descriptive process analysis, and the limits of interpreting inferred events as measurements of work.
\end{itemize}

Four research questions organize the study (Table~\ref{tab:rq}). They connect event construction to assessment, analytical use, and interpretation. The assessment distinguishes consistency with generated descriptions from accuracy against the source videos; the latter remains an open question.

The rest of the paper is organized as follows. Section~\ref{sec:relatedWork} reviews the background and related work. Section~\ref{sec:problem} defines the problem and event representation. Section~\ref{sec:pipeline} presents the construction method, and Section~\ref{sec:resource} describes the dataset and released artifacts. Section~\ref{sec:methods} explains the assessment methodology, followed by the results in Section~\ref{sec:results}. Section~\ref{sec:measurement} discusses the implications for process measurement. Section~\ref{sec:discussion} concludes the paper with the main findings, limitations, and directions for future work.
